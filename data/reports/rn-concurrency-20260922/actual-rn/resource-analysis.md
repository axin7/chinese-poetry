# RN 实机资源分析：向量查询与英文自然语言查询

本机可以在测试限额下提供全量检索，但查询期间存在明显换页和 I/O 等待。
结果不支持把“CPU 配额不够”作为主要解释，也不支持把短时最高吞吐称为稳定容量。

## 范围与窗口

数据来自 `full-host.jsonl`、两份 benchmark JSON 与 `test-budget.json`。
查询时 Qdrant 限额为 1,280 MiB RAM、RAM+swap 共 2,304 MiB、1.75 CPU；
API 为 96 MiB、0.5 CPU。启动时先用过 1,100 MiB RAM，查询前已调整。
以下北京时间窗口排除了之前的归档解压及启动过程：

- 向量阶段约 03:25:19–03:27:03，50 个主机样本，约 104 秒。
  起点按结束时间减各阶段时长推算，不包含前置预热，存在秒级边界误差。
- 英文 API 阶段 03:27:43–03:30:07；其内 68 个主机样本覆盖约 142 秒。
- 主机采样约每 2 秒一次；计数器差值仅使用窗口内首尾样本。

PSI 为窗口内累计停顿时间占比；some 表示至少一个任务因该资源停顿，
full 表示所有非空闲任务同时停顿，不能与 CPU 百分比相加。
内存上限触发表示碰到 cgroup 限制并进行回收，不等于发生 OOM。
主机指标包含其他进程，但 Qdrant 自身在两阶段也分别产生约
2,343 / 1,207 MiB 读取及 1,614 / 863 MiB 写入，与换页及缺页证据一致。

API 的 cgroup 历史 RAM 峰值仅 40.79 MiB，无 swap、OOM 或内存上限触发。
两轮查询连同间隔内，主机可用 RAM 最低 318.19 MiB，空闲 swap 最低 16.70 MiB。
查询前 03:23:40 的采样更紧张：空闲 swap 仅 0.215 MiB，
Qdrant swap 达 1,022.32 MiB；这组启动前后数据没有混入上表。

## 吞吐解释

向量阶段 292/292 成功；并发 1/2/4/8 的 QPS 为 1.90/3.29/2.23/3.72，
p95 为 0.89/1.33/3.02/4.92 秒。
英文 API 阶段 754/754 成功，返回 249 部不同作品；并发 1/2/4/8/16 的 QPS 为
1.18/2.91/5.88/9.69/9.46，p95 为 1.14/0.99/1.00/1.14/2.05 秒。

并发增加并未始终增加吞吐。两轮输入分布、预热状态及调用链不同，
不能因为英文 API 更快就推断模型调用能提高向量吞吐。
本轮只能证明这些短时样本能运行。后续中文多样查询已完成，见[最终报告](../report.md)；
持续负载与线上安全余量仍需进一步验证。
