## 返回契约

```json
{
  "match": {
    "original": "春溪與岸平，初月出溪明。——張薦",
    "translation": "春天的溪水与岸边齐平，初升的月亮从溪中升起显得明亮。",
    "sentence_index": 0,
    "score": 0.68631744
  },
  "poem": {
    "id": "yudingquantangshi:38315",
    "title": "五言玩初月重遊聯句",
    "author": "顏真卿",
    "detail_url": "/poems/yudingquantangshi%3A38315?generation=poetry-20260921-v1"
  }
}
```

以上为 HTTPS 实际响应。查询为「想找写春天花开、溪水清澈的唐诗。」。

`score` 直接来自最终选中候选的 Qdrant `Hit.Score`。当前配置为 Cosine、INT8、
HNSW 近似检索、关闭原始向量 rescore，因此应理解为当前检索配置产生的相似度分数。
它不是正确率、置信度或跨模型可比较的统一分数，也没有强制截断到 0–1。

若以后开启 rerank，`score` 仍是最终选中诗句的向量检索分数，不会混入 reranker 分数。
候选读取失败导致跳过某条结果时，分数仍与实际返回的诗句对应。
缓存路径保留相同字段；零值和负值也作为数字返回，不省略字段。

相关实现：

- `internal/model/model.go`：`SearchMatch.Score`。
- `internal/search/service.go`：候选内容与向量分数一同传递和选择。
- `internal/search/score_test.go`：ANN、重排、缺失候选、降级、缓存、零值和负值。
- `internal/model/model_test.go`：兼容原 JSON 字段并增加数字 `score`。

说明词义局部重合不等于完整意图相关。

另外发现已有语料中的 `yudingquantangshi:32662` 包含原文 `j`，
译文为「这是缺失的文字或符号。」。三个无关技术问题命中该记录，分数分别为
0.3845、0.4480、0.5329。本次只记录这一数据质量问题，未删除、补译或修改索引。
过滤无效内容需要独立、可审查的数据规则，不能把相似度阈值当作完整的数据质量方案。

## 阈值结论

本次两组分数未重叠，但输入由人工构造，负样本明显偏离古诗语境，且每组仅 12 条。
诗词主题存在覆盖程度差异，例如“登高、壮志、前行”只命中其中“志向坚定”的含义。
此外，另一条自然口语化的春景检索得到 0.6863，低于本组诗词意图最低值。
不能以本次正样本最低值直接设门槛，否则可能错误拒绝真实诗词需求。

生产阈值应使用实际场景模型生成的检索意图，增加短词、多义词、否定表达、
与古诗词汇重合但意图不符的困难负样本，并标注最终诗句是否适合展示。
再在独立验证集上比较误展示与误拒绝比例，选择明确的取舍。
更新模型、语料范围、量化或重排后需要重新校准。

当前行为保持只返回得分，未启用自动拒绝阈值。
